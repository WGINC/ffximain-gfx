## 1. The gate now gives callees only values they can really produce

Several FAILs were not translation errors. A gate stub (a stubbed callee) answered with values the
real callee never returns, so two correct programs diverged.

- **Return kinds (`ret_kinds.py`).** A forward dataflow over each function's code classifies its EAX at every `ret`:
  - `bool`: EAX is exactly 0 or 1 (975 functions);
  - `lowbool`: AL is 0 or 1 and the upper bits are left over (1,780 functions);
  - otherwise unknown.

  A stub then answers within that range. Example: `CXiActor_IsModelMissingOrFlag2000` is typed `BOOL`.
  The original tests `al == 1` and the translation tests `!= 0`. Both are right for 0/1, and only the
  gate's random 0x28 told them apart.
- **x87 returns (`fp_callsites.py`).** A stub for a float-returning callee now pushes a value onto the x87 stack. It does so only at calls where the original caller reads it:
  - the next x87 instruction on every path reads ST0;
  - or the caller returns it as its own float result.

  Before this, no stub pushed anything, so a caller that pops a float result popped an empty stack.
- **`fpret.py` corrected.** It now handles:
  - `fpatan`/`fyl2x` (pop one) and `fsincos`/`fptan`/`fxtract` (push one);
  - x87 consumers: functions whose first x87 instruction pops a value they were given, i.e. MSVC
    `__ftol` and two helpers.

  It also records `none` for functions proven to return with an empty x87 stack. 85 functions IDA typed
  as returning a float are proven `none`. They are now translated and gated as `void`. Example:
  `sub_10282A30` converts its float with `__ftol` and returns nothing on the x87 stack.
- **A trampoline bug avoided.** Unicorn caches translated code, so the stub's return trampoline is written once and never patched per call.

## 2. Translator repairs (`hx2cpp.py`)

Each repair is a rule, not a per-function edit, and applies wherever the pattern occurs:

| Rule | What Hex-Rays does | Fixed (examples) |
|---|---|---|
| Exact float constants (`fpconst.py`) | prints a single-precision constant as a short decimal, so in C++ it becomes a different double | `GetWidth/Height/DepthScale`, `GetWalkSpeed` |
| x87 status word | splits `fcom; fnstsw ax` into `c0/c2/c3` but leaves the status word unassigned | `CXiSkeletonActor_OnMove`, `Init`, `OcclusionClip`, `ZoneMap_DrawMeshById` |
| Unconsumed float callees | declares a callee `float` that the caller never reads, so GCC pops a value the original leaves | `Camera_ApplyViewProjection` |
| Signed `_DWORD` | `_DWORD` has no sign in Hex-Rays: comparisons and `/`, `%` take the other operand's sign, and unsigned is written `2u` | cursor clamp `sub_10124640`, `sub_10281DB0`, `sub_102214D0`, `sqgxVertexShaderCreate` |
| Exact stack frame | splits one stack array into several variables and writes across them through a pointer | `Actor_DrawWorldText`, `sub_10086900` |
| In-place buffers | the IDB types a global buffer as a pointer: `qmemcpy(&G, ...)` then `qmemcpy(..., G, ...)` | `sub_1011AA40`, `sub_10162010` (the viewport copies) |
| Type parsing | `void (*)()`, `__noreturn`, Windows pointer typedefs, a global named like a parameter (`::self`) | the last 3 compile failures: **712 of 712 now compile** |

## 3. Hand corrections as data (`data/hx_patches/`)

Some output cannot be repaired by a rule. Example: in `sub_10283420` Hex-Rays took the arguments pushed
before a shared `SetRenderState` call for stack variables overlapping the material struct.

- A patch is the exact snippet and its replacement, with the reason and the disassembly evidence.
- It is applied only while the export's text has the same SHA-1. A re-export after the IDB is fixed
  reports the patch as stale and never applies it silently.
- `hx2cpp.py` and `hx2clean.py` both apply patches.

## 8. Evening round: every FAIL to its root cause

Each FAIL was traced, not labelled: the gate trial replayed on both sides, with the values at the point
where they part (`localize.py`, now replaying through the gate's own `setup_trial`; ad-hoc tracers on
the callee entry points or on the memory involved). Nine FAILs were bugs in Hex-Rays' output or in the
IDB, five were the gate's model of the game, and running the gate more faithfully exposed five more
that its stubs had hidden.

**Hex-Rays and IDB errors (fixed by rule or as data)**

| Function | Root cause | Fix |
|---|---|---|
| `sub_10185CA0` | Hex-Rays lost 12 bytes of stack depth and read arguments a2/a3 as slots past the frame | patch `data/hx_patches/0x10185CA0.json` |
| `App_InitScene` | `CDx_CreateStereoResources` takes two 16-bit sizes, typed `int`: callers' leftover upper register halves looked like arguments | `data/type_fixes.json` (new: prototype corrections, applied to every reference) |
| `CXiSkeletonActor_DrawModel` | `g_modelMaterial` (a 68-byte `D3DMATERIAL8`) untyped, its template typed as a pointer: the copy used a byte as its destination | `type_fixes.json` for data |
| `Camera_ApplyViewProjection` | `sub_10021B70` returns its matrix in EAX but is typed `float`: the result was dropped | type fix + patch |
| `sub_1011E980` (and 3 more) | Hex-Rays writes the inline `x < 0 ? -x : x` and `x < 0 ? 0 : x` parity tests with never-assigned c0/c2 | rule `negate_if_negative` |
| `CXiSkeletonActor_Slot244_Unknown` | eight 4-float corner points declared as separate locals and walked with a pointer | `exact_frame` now also for a pointer walking scalar locals |
| `CDx_ApplyStereoEyeProjection` | a 4x4 matrix declared `float v3[12]; float v4;`: `Mat4_SetIdentity` wrote past GCC's array | `exact_frame` for an array followed by a local of its element type |
| (all) | the rebuilt x87 status word ignored unordered (NaN) compares, where x87 sets C0, C2 and C3 | `fpu_status_words` |
| `CXiSkeletonActor_OnMove` | IDA's SP is 4 bytes short between `call [eax+318h]` and `call [eax+3C8h]` (it took `push ebp; push edi` as the first call's arguments, and missed the second's `ret 4`): Hex-Rays gives one stack slot two names | `data/ida_sp_fixes.json`, applied in IDA by `ida_apply_names.apply_sp()`; needs a re-export |

`stack_depth.py` computes the real stack depth at each instruction; `ida_sp_check.py` reads IDA's own SP
from the listing (`[esp+27Ch+var_26C]`) and aligns it with the code instruction by instruction. That is
how the OnMove error was located. A sweep over all functions is not yet reliable: without COM-call
awareness it reports false alarms at D3D calls.

**Gate model (the gate fed inputs the game never produces)**

| Function | Root cause | Fix |
|---|---|---|
| `sub_1024CF50` | stubs logged the prototype's 4 cdecl arguments; the callee reads 2, so stale stack was compared | `cdecl_args.py`: argument slots each cdecl function really reads |
| `sub_10029A50` | a tail call through a fuzzed vtable ran fuzzed bytes as code, which used the return address (different on each side) | executing data now ends a run as a fault (not compared when the original does it) |
| `sub_1001C930` | the 80-entry ring index was fuzzed past 79 (the game wraps it at 0x4F, 0x1001BAC7) | `input_ranges.json` |
| `CXiSkeletonActor_DrawResourceShadows` | the stub of a 3-instruction getter (`*out = this->field_B4`) could not do its write | `leaf_funcs.py`: 5,112 small leaf functions now run for real, with the globals they read fuzzed |
| `CXiSkeletonActor_IsReadCompleteBody` | `ResourceHandle_IsResident` returns 0/1 in AL, but `ret_kinds` did not learn AL = 0 from `test al, al; jne` | `ret_kinds.py` (93 more 0/1 returners) |
| `Mo_InitSharedRenderResources` | an allocator stub returned NULL, which the game's callers never handle | `data/allocators.json`: allocator stubs return fresh zeroed blocks |

Running leaves for real first turned 4 PASS into FAIL and 6 into INCONCLUSIVE. All were traced: three were
real translation bugs the stubs had hidden (OnMove, StereoEyeProjection, Camera_ApplyViewProjection),
the rest the missing leaf globals, the AL return kind and the allocator. All are now PASS except OnMove.

`unset_reads.py` lists locals Hex-Rays reads but never assigns. It had flagged `Camera_ApplyViewProjection`'s
lost return value before the gate did; the other hits are mostly benign (registers passed through
unused, struct fields filled through a neighbour). Two misframed-argument cases sit in INCONCLUSIVE
functions (`sub_10017810`, `sub_10183760`), unverifiable until those get inputs.
