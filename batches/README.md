# Naming batches

The verified tree's functions that still carry a placeholder name (`fn_10082860`, `FUN_…`, `sub_…`, a vtable slot
`vf123`), in batches of related code, hottest first. Each `NNN_<group>.md` is one batch: every function's verified
C++, the facts about it, what it calls, who calls it, the vtables that hold it. `index.json` lists them.

Generated by `pipeline/batch.py` from the tree; do not edit the batch files.

## The job of a naming session
Read one batch and write `data/names/NNN_<group>.json`: a name for each function the dossier lets you name.

```json
{
  "0x100827F0": {
    "name": "CXiActor_IsStateA4Eq54",
    "confidence": "medium",
    "evidence": "returns 1 iff the int at this+0xA4 is 0x54; actor vtable slot 214 in 16 actor classes",
    "summary": "Tests whether the actor's field at +0xA4 equals 0x54."
  }
}
```

## Rules (the repository's standing rule: do not guess)
- **Only from the dossier.** Every word of a name must come from what the batch file shows: the code, the calls, the
  callers, the Direct3D methods, the imports, the vtables, DancingMad's and the PS2 build's names of its neighbours.
  If the code does not show what a thing is, the name says what the code does, not what it might be for:
  `CXiActor_IsStateA4Eq54`, not `CXiActor_IsSwimming`.
- **Skip what you cannot name.** Leave a function out of the file rather than invent a purpose. A skipped function is
  fine; a wrong name is not.
- **Form:** `Prefix_Verb…` in CamelCase parts joined by underscores, as DancingMad names things (`CDx_SetLight`,
  `CXiControlActor_IsFreeRun`, `BoneXform_PostMultiplyInto`).
  - The prefix is the batch's class when the batch is a class (`CXiActor`, `CDx`).
  - Otherwise it is the area the code belongs to, shown by its callees and callers' names (`Font_`, `Zone_`,
    `Mat4_`).
  - Getters start `Get`/`Is`/`Has`; setters `Set`; others a verb.
- **confidence:**
  - `high`: the dossier shows the purpose directly, e.g. a Direct3D method, an import, a string, a PS2 match;
  - `medium`: the behaviour is clear from the code and the names around it;
  - `low`: the name describes the code mechanically.
- **evidence:** what in the dossier shows it, in one line. **summary:** one sentence of what the function does.
- Change nothing else: no code, no other files.

## Check, commit, push
```
python3 pipeline/check_names.py batches/index.json data/names/NNN_<group>.json
```
It must print `OK`. Then commit only that file to your branch, with a message `names: batch NNN_<group> (N named,
M skipped)`, and push. Do the next batch you were given.
