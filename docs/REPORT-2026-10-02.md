## 1. The gate now gives callees only values they can really produce

Several FAILs were not translation errors. A gate stub (a stubbed callee) answered with values the
real callee never returns, so two correct programs diverged.

- **Return kinds (`ret_kinds.py`).** A forward dataflow over each function's code classifies its EAX at every `ret`:
  - `bool`: EAX is exactly 0 or 1 (975 functions);
  - `lowbool`: AL is 0 or 1 and the upper bits are left over (1,780 functions);
  - otherwise unknown.

  A stub then answers within that range. Example: `CXiActor_IsModelMissingOrFlag2000` is typed `BOOL`.
  The original tests `al == 1` and the translation tests `!= 0`. Both are right for 0/1, and only the
  gate's random 0x28 told them apart.
- **x87 returns (`fp_callsites.py`).** A stub for a float-returning callee now pushes a value onto the x87 stack. It does so only at calls where the original caller reads it:
  - the next x87 instruction on every path reads ST0;
  - or the caller returns it as its own float result.

  Before this, no stub pushed anything, so a caller that pops a float result popped an empty stack.
- **`fpret.py` corrected.** It now handles:
  - `fpatan`/`fyl2x` (pop one) and `fsincos`/`fptan`/`fxtract` (push one);
  - x87 consumers: functions whose first x87 instruction pops a value they were given, i.e. MSVC
    `__ftol` and two helpers.

  It also records `none` for functions proven to return with an empty x87 stack. 85 functions IDA typed
  as returning a float are proven `none`. They are now translated and gated as `void`. Example:
  `sub_10282A30` converts its float with `__ftol` and returns nothing on the x87 stack.
- **A trampoline bug avoided.** Unicorn caches translated code, so the stub's return trampoline is written once and never patched per call.

## 2. Translator repairs (`hx2cpp.py`)

Each repair is a rule, not a per-function edit, and applies wherever the pattern occurs:

| Rule | What Hex-Rays does | Fixed (examples) |
|---|---|---|
| Exact float constants (`fpconst.py`) | prints a single-precision constant as a short decimal, so in C++ it becomes a different double | `GetWidth/Height/DepthScale`, `GetWalkSpeed` |
| x87 status word | splits `fcom; fnstsw ax` into `c0/c2/c3` but leaves the status word unassigned | `CXiSkeletonActor_OnMove`, `Init`, `OcclusionClip`, `ZoneMap_DrawMeshById` |
| Unconsumed float callees | declares a callee `float` that the caller never reads, so GCC pops a value the original leaves | `Camera_ApplyViewProjection` |
| Signed `_DWORD` | `_DWORD` has no sign in Hex-Rays: comparisons and `/`, `%` take the other operand's sign, and unsigned is written `2u` | cursor clamp `sub_10124640`, `sub_10281DB0`, `sub_102214D0`, `sqgxVertexShaderCreate` |
| Exact stack frame | splits one stack array into several variables and writes across them through a pointer | `Actor_DrawWorldText`, `sub_10086900` |
| In-place buffers | the IDB types a global buffer as a pointer: `qmemcpy(&G, ...)` then `qmemcpy(..., G, ...)` | `sub_1011AA40`, `sub_10162010` (the viewport copies) |
| Type parsing | `void (*)()`, `__noreturn`, Windows pointer typedefs, a global named like a parameter (`::self`) | the last 3 compile failures: **712 of 712 now compile** |

## 3. Hand corrections as data (`data/hx_patches/`)

Some output cannot be repaired by a rule. Example: in `sub_10283420` Hex-Rays took the arguments pushed
before a shared `SetRenderState` call for stack variables overlapping the material struct.

- A patch is the exact snippet and its replacement, with the reason and the disassembly evidence.
- It is applied only while the export's text has the same SHA-1. A re-export after the IDB is fixed
  reports the patch as stale and never applies it silently.
- `hx2cpp.py` and `hx2clean.py` both apply patches.
